# Forvilla — Research Brief

*Prepared 2026-07-03*

## What Forvilla is

Forvilla is a mobile app (iOS, Lifestyle category) built around the tagline **"For the village."**
Rather than being an online store, it brings people together **in person** around local handmade
markets — farmer's markets, art markets, vintage markets, and community pop-up events.

Developer: **Linda Yeung** (independent developer). Social presence: Instagram
[@forvilla_project](https://www.instagram.com/forvilla_project/).

## Core features (relevant to this assignment)

| Feature | Why it matters for vendor data |
|---|---|
| Live 2D event map with vendor booth locations | Vendor records need **booth assignments** per event |
| Artisan "mini hub" profiles (signature items, story, market calendar) | Vendor records need **category, products, story-ready info** |
| Vendor market calendar / favorites with updates | Vendors must be **linked to events** consistently (IDs, not just names) |
| Social media connectivity to vendor pages | **Instagram handles** must be normalized and valid |
| Category-based booth highlights | Categories must come from a **controlled taxonomy**, not free text |

## Brand voice (used for the social media posts)

- Warm, inclusive, community-centered.
- Signature vocabulary: **"villagers," "the village," "makers," "come out"**.
- Celebrates authenticity and the story behind each artisan.
- Playful, not corporate — emoji-friendly, invitational tone ("come out and meet…").

## Implications for the assignment

1. **Uploads** should be one clean, consistently-shaped file per event plus a master file —
   matching how the app links vendors → events → booths.
2. **Data quality** directly powers app features (map booths, calendars, category filters,
   social links), so validation must be automated and repeatable, not eyeballed.
3. **Social posts** should sound like Forvilla: village language, vendor lineups by category,
   and per-vendor spotlights that tease the artisan's story.
