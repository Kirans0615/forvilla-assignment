# Project Plan — Forvilla Vendor Data & Social Content

**Goal:** Upload vendor lists for 10 upcoming handmade market events, guarantee data quality and
consistent formatting, and convert the data into ready-to-publish social media posts.

## Phase 0 — Research (done)
Understand Forvilla's product and voice so the data model and copy fit the app.
→ Output: `docs/research-brief.md`

## Phase 1 — Define the data standard
Before touching data, write down what "clean" means: required fields, a controlled category
taxonomy, and one canonical format for every field (dates, times, phones, Instagram handles,
emails, booth codes).
→ Output: `docs/data-standards.md`

## Phase 2 — Intake the raw vendor lists (10 events)
Collect one vendor list per event as delivered (spreadsheets from market organizers arrive in
inconsistent shapes). In this build the raw files are **simulated intake data** generated by
`scripts/00_make_sample_raw.py`, reproducing the real-world mess: mixed date/phone formats,
free-text categories, Instagram URLs vs handles, duplicates, stray whitespace, missing contacts.
→ Output: `data/raw/events.csv` + `data/raw/EVT-0XX_*.csv` (10 files)

## Phase 3 — Clean & normalize (the "upload-ready" step)
A repeatable script applies the Phase 1 standard to every raw file:
dedupe, normalize every field, map categories onto the taxonomy, assign stable vendor IDs,
and join vendors to events.
→ Output: `data/clean/events.csv`, `data/clean/vendors_EVT-0XX.csv` (10 files),
`data/clean/all_vendors_master.csv` — these are the files to upload into Forvilla.

## Phase 4 — Validate (prove the quality)
An independent script re-checks the cleaned output against the standard (formats, taxonomy,
duplicates, referential integrity, completeness) and writes a pass/fail report, including a
follow-up list of vendors with missing contact info.
→ Output: `reports/data_quality_report.md`

## Phase 5 — Convert to social media posts
Generate, per event, in Forvilla's voice: an Instagram announcement, a Facebook post, and a
vendor spotlight — plus a posting calendar (announce 7 days out, spotlight 3 days out,
reminder 1 day out).
→ Output: `social/EVT-0XX/` (30 posts) + `social/content_calendar.csv`

## Phase 6 — Documentation
README covering what was delivered, how to re-run the pipeline, and how to swap in real
vendor files.
→ Output: `README.md`

## Success criteria
- 10 event vendor lists in identical, upload-ready shape; validation report shows 0 errors.
- Every social post uses real fields from the clean data (no placeholders) and Forvilla's voice.
- Entire pipeline re-runs with one command when real data replaces the samples.
